# Local TTS + streaming STT survey — whisper-register voice lane

Date: 2026-07-03 · Target hardware: Apple M4 Max, 128 GB · Scope: companion stream voice-lane decision (see [GOAL.md](../GOAL.md) — "presence through headphones", sub-500 ms round-trip question).

Method: desk research only. **No installs, no downloads, no local benchmarks were run.** Every number below is a third-party measurement with a link; hardware and conditions vary per source, so treat numbers as order-of-magnitude until the latency harness reproduces them locally. Claims marked `[inference]` are reasoned, not measured.

Terms: **RTF** = real-time factor. Two conventions exist in the wild; here RTF < 1.0 = faster than real time, and "×RT" = speedup multiple (22×RT ≡ RTF 0.045). **TTFA** = time-to-first-audio.

## Top picks

**TTS #1 — Kokoro-82M via mlx-audio (or CoreML), voice `af_nicole`.** The only local engine with a purpose-trained ASMR/whisper voice *and* proven interactive latency on exactly our chip class: ~100 ms warm TTFA on M4 [[S1](https://blog.dtelecom.org/we-replaced-elevenlabs-with-kokoro-tts-on-an-m4-gpu-latency-fell-to-100-ms-and-tts-cost-nearly-68bcc3313cdd)], 22×RT MLX on M4 Max [[S2](https://github.com/waybarrios/vllm-mlx/blob/main/docs/benchmarks/audio.md)], Apache-2.0, ~170–300 MB.

**TTS #2 — F5-TTS (f5-tts-mlx) as the whisper-register cloning lane.** Zero-shot voice matching from a 5–10 s whispered reference clip [[S19](https://github.com/lucasnewman/f5-tts-mlx)] gives a *true* breathy close-talk register Kokoro can't reach when `af_nicole` isn't intimate enough — but at ~4 s per utterance on M3 Max it's for pre-rendered/async lines (greetings, ambience beds), not the realtime loop; weights are CC-BY-NC-4.0 [[S20](https://huggingface.co/SWivid/F5-TTS)] (fine for this personal project, blocks commercialization). Runner-up: Chatterbox (MIT, `exaggeration` dial) if licensing ever matters more than its sub-real-time RTF 0.65–0.74 on M4 [[S22](https://pypi.org/project/chatterbox-mlx/)].

**STT — parakeet-mlx (tdt-0.6b-v3) + Silero VAD v5 for endpointing.** Native MLX streaming partials with draft/finalized token split [[S26](https://github.com/senstella/parakeet-mlx)] at 52–117×RT [[S2](https://github.com/waybarrios/vllm-mlx/blob/main/docs/benchmarks/audio.md), [S3](https://soniqo.audio/benchmarks)] means STT compute is never the bottleneck — the whole STT latency budget collapses into the VAD trailing-silence window, which Silero evaluates in <1 ms/chunk [[S31](https://github.com/snakers4/silero-vad)] and we can tune to ~300–500 ms. Fallback: whisper.cpp `whisper-stream` if Parakeet's English/EU-language limit [[S3](https://soniqo.audio/benchmarks)] bites.

### Implied round-trip budget `[inference — for LatencyHarness to verify]`

VAD endpoint wait ~300–500 ms + Parakeet finalize ~tens of ms [[S2](https://github.com/waybarrios/vllm-mlx/blob/main/docs/benchmarks/audio.md)] + LLM first-sentence + Kokoro TTFA ~100 ms [[S1](https://blog.dtelecom.org/we-replaced-elevenlabs-with-kokoro-tts-on-an-m4-gpu-latency-fell-to-100-ms-and-tts-cost-nearly-68bcc3313cdd)] → the speech stack fits inside GOAL.md's sub-500 ms floor excluding the LLM; the LLM's first-token/first-sentence time will dominate.

## Whisper-register notes (why this column exists)

- Kokoro's `af_nicole` was trained on 10–100 h of headphone-register data (the 🎧 trait) [[S7](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)] — soft, breathy, slow delivery [[S8](https://voicerankings.com/voice/kokoro-82M/female/af_nicole)]. Kokoro also supports voice-vector blending [[S9](https://github.com/thewh1teagle/kokoro-onnx/blob/main/examples/with_blending.py)], so `af_nicole` can be mixed with a higher-grade voice (e.g. `af_heart`, grade A [[S7](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md)]) to trade intimacy against articulation.
- Cloning engines (F5, Chatterbox, OuteTTS) reach whisper register through the reference clip, not a parameter — record one good whispered reference and it becomes the persona's "soft mode" `[inference from documented voice-matching mechanisms, S19/S21/S22]`.
- Any engine's output can be pushed *toward* whisper with DSP (de-voicing/noise excitation, high-pass, compression) but timbre realism suffers; treat as garnish on the presence layer, not the plan `[inference]`.
- Controllability summary: Kokoro = speed param + inline IPA phonemes via misaki [[S11](https://huggingface.co/hexgrad/Kokoro-82M)], no SSML. Piper = speed/noise scales, no SSML [[S12](https://github.com/OHF-Voice/piper1-gpl)]. AVSpeechSynthesizer = rate/pitch/volume + SSML input and Personal Voice [[S17](https://developer.apple.com/videos/play/wwdc2023/10033/)]. Chatterbox = `exaggeration` + CFG weight [[S22](https://pypi.org/project/chatterbox-mlx/)]. Dia = nonverbal tags [[S24](https://github.com/nari-labs/dia)].

## Cloud comparators (for the local-vs-cloud tradeoff only)

ElevenLabs' Flash models run ~75 ms **model inference** for short inputs, but ElevenLabs' own docs stress that user-perceived TTFA adds 20–200 ms network round-trip plus player buffering (a 500 ms buffer being common) [[S32](https://elevenlabs.io/docs/eleven-api/concepts/latency)]; one team measured 250–300 ms TTFA from the ElevenLabs API vs ~100 ms for local Kokoro on an M4 in the same pipeline [[S1](https://blog.dtelecom.org/we-replaced-elevenlabs-with-kokoro-tts-on-an-m4-gpu-latency-fell-to-100-ms-and-tts-cost-nearly-68bcc3313cdd)]. OpenAI's Realtime API shows ~500 ms time-to-first-byte in sustained third-party testing [[S33](https://www.latent.space/p/realtime-api)], with developer reports ranging ~250–800 ms depending on prompt size [[S34](https://community.openai.com/t/is-the-realtime-api-actually-realtime/1050130)]. Net: local Kokoro on this hardware beats cloud TTFA while removing per-character billing and keeping audio on-device — cloud only wins on voice catalog breadth and polish [[S1](https://blog.dtelecom.org/we-replaced-elevenlabs-with-kokoro-tts-on-an-m4-gpu-latency-fell-to-100-ms-and-tts-cost-nearly-68bcc3313cdd), [S32](https://elevenlabs.io/docs/eleven-api/concepts/latency)].
