# AniChat expressive-stack gap audit

_As of 2026-07-16. Audit only; no implementation is proposed here._

## Scope and evidence boundary

The archaeology note separates the current Grok client from the older local AniChat predecessor and explicitly warns that their motion equivalence is unknown (`streams/companion/notes/anichat-pipeline-recon.md:15-18,98-100`). The investigation bundle likewise says all model probes apply to `older_anichat`, not current Grok (`streams/companion/notes/anichat-grok-pose-investigation/research-report.md:1-5`; `streams/companion/notes/anichat-grok-pose-investigation/probe-findings.md:1-8`). “AniChat” below therefore means the observed predecessor architecture, not an asserted property of today’s Grok app.

Status meanings:

- **Shipped** — behavior is present in the current browser stack, not merely named in a design document.
- **Partial** — the current stack has a useful analogue, but not the AniChat-grade capability named in the row.
- **Missing** — no such mechanism is present in the inspected shipped public path; this is a gap against the predecessor evidence, not proof about uncached current Grok bundles.

## The emotion-vector suspicion, precisely

Arthur’s suspicion is **wrong for the frozen contract, but right about the remaining gap**:

1. **AffectVector VAD, EmotionMix anchors, and `setAffect`/L0 projection did ship.** The frozen contract defines VAD, named palette weights, persona-owned anchors, channel manifests, and lane ordering (`apps/ai-companion-rtc/docs/expressive-stack.md:7-16`). The browser handle exposes `setAffect`, and the state carries both the named mix and VAD vector (`apps/ai-companion-rtc/public/vrm-body.ts:60-66,135-151`). `setAffect` stores lane, TTL, intensity, VAD, and mix, then prepares degraded expression targets and named pose accents (`apps/ai-companion-rtc/public/vrm-body.ts:895-940`). The ARKit path projects valence/arousal/dominance plus mix accents into brows, eyes, cheeks, mouth, and jaw (`apps/ai-companion-rtc/public/vrm-body.ts:609-648`), while the runtime chooses ARKit or degraded expression projection and applies bounded attack/decay envelopes (`apps/ai-companion-rtc/public/vrm-body.ts:2314-2382`).
2. **AniChat-style conditioning goes beyond a semantic emotion vector.** The older model family exposes separate face/body/wrist embedding-denoiser-decoder pipelines, 8-frame decoder chunks, explicit history tensors, audio features, timestep, class labels, gaze, and body-motion-latent inputs (`streams/companion/notes/anichat-grok-pose-investigation/static-findings.md:27-42`). Probes show the history inputs are materially load-bearing, while audio changes one denoiser output under the synthetic intervention (`streams/companion/notes/anichat-grok-pose-investigation/probe-findings.md:46-69,124-152`). Those findings establish an audio/history-conditioned motion interface, **not** semantic emotion labels or a proven production caller loop; outputs stay anonymous with no semantic claim (`streams/companion/notes/anichat-grok-pose-investigation/runtime-findings.md:99-105`) and the denoising objective/scheduler remains unknown (`streams/companion/notes/anichat-grok-pose-investigation/research-report.md:91-99`).
3. **Our current analogue is audio-energy texture, not a regional learned generator.** The shipped L0 smooths speech energy and uses it for mouth openness, head/neck bob, emphasis, chest, arms, and hands (`apps/ai-companion-rtc/public/vrm-body.ts:1826-1866,2269-2278`). The investigation’s clean adoption boundary is therefore correct: any future audio-conditioned worker belongs below semantic arbitration and must produce bounded residual motion with deadline miss → drop/decay, never queue (`streams/companion/notes/anichat-grok-pose-investigation/research-report.md:239-249`).

## Top-three genuine gaps: next milestone plans only

These are reviewable plans, not a build order or authorization to implement.

| Priority | Gap to close | Concrete milestone plan | Review gate before any build |
|---|---|---|---|
| 1 | AniChat-like audio/history regional residual | **Define the contract first:** document audio feature shape/source, history slot count and reset reasons, chunk duration, region mask, playback anchor, confidence, and maximum authority. Keep semantic `MotionPrimitive`/affect lanes authoritative; admit only bounded additive deltas below them. Specify late/deadline behavior as drop/decay and never queue; specify model-swap and interruption resets. | A written manifest plus timeline traces showing semantic ownership, epoch/history fencing, and late-chunk rejection. No model selection, scheduler, or worker implementation until this contract is reviewed. Proposed seam fields are already enumerated by the investigation bundle (`streams/companion/notes/anichat-grok-pose-investigation/research-report.md:261-294`). |
| 2 | Authored material regions/masks | **Inventory and taste-test the art contract:** enumerate optional face-shadow, hair/specular, matcap, AO, opacity, and blush/emissive roles; decide whether each is texture-mask, scalar shader parameter, or both; define per-character fallbacks and safety ranges; then specify one inspectable profile format that remains renderer-owned and L0-written. | One reviewed profile fixture per chosen hero avatar, a missing-parameter fallback report, and an A/B screenshot checklist. Do not add shader controls until the desired regional look and licensing boundary are accepted; current profiles intentionally expose no shader parameters (`apps/ai-companion-rtc/public/rig-profiles.ts:345-429`). |
| 3 | Spring/jiggle secondary motion | **Choose the motion vocabulary before physics:** select a bounded set of intent groups (for example hair, cloth, accessory), choose spring parameters or authored response curves, define fixed-step/stability limits, and specify how secondary motion yields during capture, actions, model swaps, and interruption. Keep it below semantic bones and expose an explicit disable/degrade path. | A written group manifest, stability/overshoot thresholds, and a short review capture showing semantic pose unchanged when secondary motion is disabled. Do not begin a spring implementation or import a physics runtime from this audit. |

Dependable authored states and blendshape choreography remain important **partial** gaps, but they should follow the authority decision above: their current primitives already work, while their asset grammar and character-specific performance language do not. Curves-as-assets and per-character profiles are enabling contracts for that later pass, not reasons to replace the frozen VAD/L0 control plane.

## Proposed Xanadu question

**Title:** Which expressive gap should define the next review?

**Body:** VAD + EmotionMix anchors + `setAffect`/L0 projection are shipped. The taste fork is what comes next: (A) AniChat-like audio/history regional residuals under semantic authority; (B) hero-character material regions/masks and secondary motion; (C) dependable authored states plus blendshape choreography and easing assets; or (D) more portable per-character rig profiles. Which option best matches the desired companion feeling, and what are we explicitly willing to leave plain? **Bounded next-step menu:** choose exactly one option for a contract review, or choose “no build—collect evidence” and name the evidence.
