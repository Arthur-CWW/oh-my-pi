# P4a outbox ingest report

Started after reading the M1 contract, P1 report, and existing ledger/schema/error sources.

## Files

- `src/outbox.ts` — outbox envelope Schema, JSON value Schema, synchronous append helper, session outbox path helper, and env-driven default outbox directory.
- `src/ingest.ts` — one-shot JSONL ingest Effect requiring `LedgerStore`; known-kind payload schemas map to `BatchRow`s, unknown/future lines become generic events, malformed/schema-failed lines become `ingestError` events, writes commit in configurable chunks, nullable optional columns accept explicit `null`, per-kind decoders ignore publisher telemetry extras, and captured publisher raw requests materialize as ledger artifacts for model calls.
- `src/index.ts` — additive exports for outbox and ingest APIs.
- `test/ingest.test.ts` — fixture covering all wire kinds, explicit null optional fields, ignored extra payload keys, unknown kind, malformed line, future version, double-ingest idempotency, and append/re-ingest resume behavior.
- `test/publisher-ingest.test.ts` — seam guard that drives the real OMP publisher through two turns/two model calls, ingests the resulting outbox, asserts captured raw-request artifact linkage, and verifies re-ingest inserts nothing.

## Design notes

- Known row ids prefer publisher-supplied payload ids where present; otherwise non-turn rows fall back to `${sessionId}:${seq}`, turns fall back to `${sessionId}:turn:<turnIndex>`, sessions use `sessionId`, and artifacts retain the existing sha256-derived ledger identity.
- Valid unknown-kind and future-version lines store the raw JSONL line as the generic event payload so the original wire record is preserved.
- Malformed JSON/envelope decode failures have no trusted envelope id, so their `ingestError` event id is deterministic from file path, line number, and raw line content.
- Ingest never imports `bun:sqlite`; all ledger writes go through `LedgerStore.ingestBatch`.
- After the publisher seam failure, canonical schemas accept explicit `null` for nullable/optional columns and normalize those values to `undefined` before handing rows to `LedgerStore`.
- Turn row ids prefer the publisher payload id (`${sessionId}:turn:<turnIndex>`) and fall back to the same formula from `seq`; other row ids prefer payload ids where present and otherwise stay envelope-derived.
- Publisher event payloads that are already JSON strings are stored as-is to avoid double-escaping; non-string JSON payloads are stringified at the ledger boundary.
- Captured model-call `rawRequest` payloads are written through `LedgerStore.putArtifact` as `rawRequest` artifacts with default retention before the model_call row is batched; content-addressed artifact ids keep re-ingest idempotent.
