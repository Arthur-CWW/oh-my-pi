## Columns and indexes added
- `model_calls.entryId TEXT NULL` — harness session JSONL entry id for the assistant message produced by the model call.
- `model_calls.upstreamProvider TEXT NULL` — true upstream provider when a routed provider is used.
- `model_calls_session_entryId_idx` on `(session, entryId)`.

## Migration
- Bumped `LEDGER_SCHEMA_VERSION` to `2`.
- Added exported `migration0002Sql` with two `ALTER TABLE model_calls ADD COLUMN` statements, index creation, and `PRAGMA user_version = 2`.
- Kept `migration0001Sql` frozen.
- `migrateLedger` now runs 0001 for version < 1 and 0002 for version < 2, so fresh DBs receive 0001 then 0002 and v1 DBs upgrade in place.

## API and wire contract
- `ModelCallInput` accepts optional `entryId` and `upstreamProvider`; absent values are inserted as SQL NULL.
- `ModelCallFilters` accepts optional exact-match `entryId`.
- Model call query rows select the full Drizzle row, so returned objects include `entryId` and `upstreamProvider`.
- `ingest.ts` accepts optional/nullable `entryId` and `upstreamProvider` on modelCall payloads and maps null/absent values to omitted ledger input fields.
- CLI `model-calls` accepts `--entry <id>` / `--entry=<id>` and includes both fields in tabular output. JSON output still serializes library result rows directly.
- `src/index.ts` exports `migration0002Sql` alongside `migration0001Sql`.
