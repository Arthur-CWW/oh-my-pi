# Repository Guidelines

## Project Structure & Modules
- `src/`: React + TypeScript app (components, lib, styles).
- `server.ts`: Bun HTTP API serving `/api/tweets` from `tweets.db`.
- `scripts/convert-csv-to-sqlite.ts`: CSV → SQLite import utility.
- `tweets.db`: SQLite database (generated by convert script).
- `index.html`, `vite.config.ts`, `tailwind.config.js`, `postcss.config.js`.

## Build, Test, and Development
- `bun install`: Install dependencies.
- `bun run dev`: Start Vite dev server at `http://localhost:3000`.
- `bun run server`: Start Bun API server at `http://localhost:3001`.
- `bun run convert`: Import `gcr-tweets.csv` into `tweets.db` (idempotent replace).
- `uv run python -m tweet_hydrator`: Hydrate missing tweets from Wayback/Twitter into the local SQLite archive (resumes pending work by default).
- `vite build`: Produce production build in `dist/`.

Tip: Run API and frontend in separate terminals during development.

## Coding Style & Conventions
- Language: TypeScript (strict mode). React with functional components.
- Imports: Use path alias `@/*` (see `tsconfig.*`).
- Indentation: 2 spaces; prefer named exports when sensible.
- Styling: Tailwind CSS utility classes in JSX.
- Keep components small; colocate helpers in `src/lib`.

## Testing Guidelines
- Framework: Not configured yet. Prefer Vitest + React Testing Library.
- Suggested locations: `src/**/*.test.ts(x)` or `src/__tests__/*`.
- Commands (after setup): `vitest` (watch), `vitest run --coverage`.
- Aim for tests around data parsing and component rendering of tweets.

## Commit & Pull Requests
- Commits: Use imperative, scoped messages. Recommended Conventional Commits:
  - Examples: `feat(ui): add tweet media`, `fix(api): handle empty db`.
- PRs: Include description, linked issues, steps to verify, and screenshots for UI.
- Keep PRs focused and small; update docs when behavior/config changes.

## Security & Configuration
- CORS: `server.ts` allows `*` for development. Restrict origins for production.
- Data: `tweets.db` and `gcr-tweets.csv` are local artifacts. Avoid committing sensitive data.
- Env: No `.env` required currently. Prefer explicit config and document changes in README.

## Architecture Overview
- Frontend requests tweets from `GET /api/tweets` (Bun + `better-sqlite3`).
- UI mimics Twitter; counts formatted client-side; media rendered from `media_urls`.
