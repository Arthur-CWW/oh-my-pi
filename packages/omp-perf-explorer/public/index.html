04 / TRANSFERABLE MECHANISM

Borrow the page lifecycle, not the terminal

PR #13264 ↗Demo video ↗

WHAT TRANSFERS

Idle, incremental, reversible

  • Wait 250 ms after activity.
  • Compress inactive pages in ~1 ms passes.
  • Hydrate only when the viewport asks.
  • Release backing pages to the OS.

Measured upstream Demo scrollback: 25 MB → 2 MB, about 90%, while preserving I/O throughput.

WHAT DOESN’T

No drop-in compressor

  • libghostty-vt exposes whole-terminal, caller-driven APIs.
  • It is not generic byte compression.
  • The public Zig API is unstable.
  • Vendor nothing until our page boundary is proven.

Optional isolated Zig/native page store comes after HR-133 defines paging and hydration semantics.

05 / EXECUTION ORDER

The fleet substrate comes first

HR-115 makes safe cold recycle possible. The View split then unlocks focused paging and a truthful progress surface.

06 / PROOF & REFRESH

A build can be current while a View is stale.

Build identity tells us what code is installed. View identity tells us which running process has loaded it. A restart is required for Runner or server changes; a browser refresh is sufficient for static View assets.
