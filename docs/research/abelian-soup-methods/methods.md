### March 16 "pleorama slopcore" architecture

Abel describes an LLM-driven harness:

1. "a harness of visual effects for future agents to select from"
2. "pipelines to nbp and local audio/vidgen"
3. "an opinionated template about what layers a scene should have"

### Audioreactive latent-walk pipeline

In the May 15 thread, Abel describes the flow as:

> "latent ordering of the image space (vit-blended embedding [dinov2/clip/colour histogram guardrail] → cosine sim + ann clustering), timing calculate to song tempo, downbeats etc, then FILM (frame interpolation) to smooth transitions between consecutive pairs"

He later says the audioreactive pipeline still needs motion timing work:

He linked the public code repository `https://github.com/abeliansoup/latwalk` "for posterity".

### Facts from the linked `latwalk` README

`latwalk` is a Python project. Its README says it turns an image folder into an ordered visual walk by embedding images with CLIP, DINO, color histograms, or a weighted ensemble, ordering adjacent images by visual similarity, and rendering an MP4. With audio, image changes and effects can follow beat, fast onset clusters, and pulse energy.

Named models / libraries in the README:

- DINO image embeddings: `vit_base_patch14_dinov2` via `timm`.
- CLIP image embeddings: `ViT-B-32` with `laion2b_s34b_b79k` via `open_clip`.
- FILM interpolation: Google FILM via TensorFlow Hub (`https://tfhub.dev/google/film/1`).
- Experimental VAE walk: `madebyollin/taesd` via Diffusers.
- Subtitle ASR on Apple Silicon: `mlx-community/whisper-large-v3-turbo` via MLX Whisper.
- Subtitle ASR on CUDA: `nvidia/parakeet-tdt-0.6b-v3` via NVIDIA NeMo.

Named feature/order recipes:

- Default `auto` prefers DINO-heavy ensemble features when available.
- Strongest general feature recipe stated: `dino=0.55,clip=0.35,hist=0.10`.
- Ordering options include `nn`, `localnn`, `nn2opt`, `tsp`, `ann`, `tsp_or`.
- The README recommends `--order localnn`, `--full-matrix-threshold 12000`, `--distance-precision float32`, `--multistart 32`, and `--smooth-window used-images` for quality.

Named render/effect controls:

- `--effect-preset pulse`: pulse brightness/color with audio.
- `--effect-preset pulse-negative`: short negative flashes on strong pulses.
- `--effect-preset glitch`: chromatic offsets and pulse-triggered glitch bands.
- `--effect-preset rave`: stronger glitch preset.
- `--reactive-brightness`, `--reactive-zoom`, `--chromatic-shift`, `--negative-frames`, `--negative-trigger-stride`, `--glitch-trigger-stride`.
- `--noise-mode {off,speckle,grain,pulse-speckle}` for kinetic noise overlays.
- `--effect-backend cupy` can use CuPy for pixel effects; otherwise CPU/OpenCV is used.

Named audio-timing modes:

- `beat`: estimated beat grid only.
- `middlepath`: preferred general-purpose mode; snaps weak beats toward nearby stronger onsets, keeps strong off-grid accents, suppresses weak grid-only changes, and allows dense fast clusters when onset activity is high.
- `hybrid`: starts from the beat grid and adds onset-driven candidates, dense regions, fast onset clusters, capped half-beat changes, and optional midpoint inserts.

Diagnostics:

- `audio_timing_audit.py` writes `changes.csv`, `beats.csv`, `onset_peaks.csv`, and `timing_plot.png` for beat/onset/change timing audits.

Output/render numbers:

- Tweet media observed: 1280×720, 1080×1080, 1446×1434, 1926×1440, 2638×1770, 1920×1280, 1104×1080.
- `latwalk` examples and recipes include 1080×1080 and 720×720 outputs, 30 fps render recipes, `--source-fps 12 --factor 2` as the default FILM recipe, 512px as a practical first FILM target, 720px as a higher-quality local FILM target, and short tests before full 1080p FILM.
- README advice: keep `--crossfade-frames 0` when using FILM because crossfading before FILM can smear/jitter transitions.

Architecture / modularity from the repo:

- Main scripts include `walk_images.py`, `latent_walk.py`, `film_interpolate.py`, `video_reactive_film.py`, `subtitle_morph.py`, `subtitle_atlas.py`, `audio_timing_audit.py`, and `download_nga_images.py`.
- The reusable `latmatch/` package contains at least `nga_downloader.py` and `subtitle_atlas.py`, so parts of the pipeline are designed as reusable modules rather than one monolithic script.

## INFERENCE — my reading, not directly stated

- The March 16 harness is best understood as an LLM-agent orchestration layer above conventional generators and compositors: Claude chooses narrative, assets, effects, and layer composition, while prebuilt tools do the rendering/generation work.
- The key creative constraint is not one shader or pass; it is the combination of a style guide, a finite menu of effects, an opinionated scene-layer template, and manual QA/rerolls.
- `nbp` remains unresolved. It may be an internal abbreviation or typo; do not build against that term without more evidence.
- Abel's Pleometric relationship is influence/collaboration/social proximity, not identity. The public thread presents @pleometric as a separate account giving style advice.
- The `latwalk` repo likely represents the May 15 audioreactive visualiser implementation or a cleaned-up public version of it, because Abel linked it directly in that thread and its README matches the described DINO/CLIP/histogram/FILM flow.
- The Doom fire post is evidence of a technique in Abel's graphics toolbox, but it is not proof that Doom fire is part of the Pleometric-style harness.
- His pipeline appears offline/batch, not real-time: generate/select assets, compose/render, inspect, reroll.

## Mapping to our scene.v1 renderer

### Techniques that map to existing capabilities

| Abel technique | Our existing surface | Notes |
| --- | --- | --- |
| Harness of selectable visual effects | scene.v1 pass stack | Existing passes cover bloom, chromatic aberration, VHS, glitch, feedback, displacement, halftone. |
| Effect compositions/layering | scene layers + pass chains | Direct conceptual match. |
| Complex transforms / shader work | GLSL shader passes | Existing displacement/feedback/glitch passes cover part of this. |
| Audioreactive timing to tempo/downbeats | beat-synced tracks | Direct match at concept level. |
| Pulse brightness/color | bloom/exposure/color parameters keyed to beat tracks | Needs presets, not core renderer work. |
| Chromatic offsets | chromatic aberration pass | Direct match. |
| Glitch bands / rave preset | glitch + VHS passes | Direct match or near match. |
| Kinetic noise / speckle / grain | VHS/noise/glitch overlays | Partially covered. |
| Negative flashes | color/invert flash keyframes | Can be expressed as timed color inversion if supported in scene params. |
| Clone/field visual language | clone fields | Existing target vocabulary already includes this. |
| FILM-smoothed transitions | not a render pass, but analogous to tweening/interpolation | Our runtime renderer can interpolate parameters; it does not do neural FILM. |

### Concrete gaps

1. **LLM agent driver** — No Claude/Opus-style autonomous planner that turns a topic prompt into script, scenes, asset choices, pass choices, and layer composition.
2. **Style-guide constraint system** — @pleometric's advice was to constrain style guides; scene.v1 needs named style presets/rules rather than only raw parameter freedom.
3. **Opinionated scene-layer template** — Our schema is flexible; Abel's harness has a fixed opinion about what layers a scene should have.
4. **Automated asset selection/fetching** — Abel says Opus selects and fetches background video/audio assets; our renderer does not curate assets.
5. **Local audio/TTS generation** — No integrated echotts/local audio/TTS pipeline.
6. **Local vidgen integration** — No Wan/AI-video generation stage for source clips.
7. **Latent image walk mode** — We have clone fields and passes, but not a DINO/CLIP/color-histogram image-space ordering renderer.
8. **Onset-cluster timing controls** — Beat tracks exist, but `middlepath`/`hybrid`-style onset snapping, dense clusters, and timing audit CSV/PNG tooling are missing.
9. **FILM post-pass** — Our renderer has interpolation, but not Google FILM neural frame interpolation as a post-process.
10. **Doom fire pass** — Explicit classic framebuffer fire algorithm is not currently a named pass.
11. **Epilepsy/strobe QA** — Abel manually rerolls epilepsy-trigger scenes; we have no automated strobe/flash safety check.
12. **Reusable downloader/subtitle modules** — `latwalk` has reusable NGA downloader and subtitle atlas pieces; our scene stack has no equivalent content ingestion/subtitle-atlas modules.

## Practical takeaways for style vocabulary

- Treat "Pleometric-style" as an agent-composed layered video grammar, not just a shader look.
- Preserve strong named presets: pulse, pulse-negative, glitch, rave, kinetic noise, negative flash, chromatic shift, complex transform.
- Add a style-preset layer above raw passes so an agent can choose coherent bundles without freeforming every uniform.
- Build beat/onset timing as first-class scene data: beats, downbeats, off-grid accents, dense clusters, and hold/accelerate envelopes.
- Add safety diagnostics for strobe/epilepsy risk if the renderer will generate high-frequency glitch or negative-flash clips.
