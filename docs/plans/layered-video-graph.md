# Layered Video Graph Architecture Plan

## Goal

Build toward a ComfyUI-like, reversible graph for shortform video creation: modular nodes, reusable assets, editable layers, and resumable runs.

The prototype videos are not the end goal. They are test cases for a pipeline that can later create both surreal/brainrot videos and less-brainrot AI UGC/ad videos.

## Core principle

Do **not** one-shot whole videos when components can be separated.

Prefer:

```txt
source/inspiration
→ script/hook/dialogue
→ character asset(s)
→ prop/brainrot asset(s)
→ background/scene layer(s)
→ motion/video generation
→ voice/TTS
→ lipsync or mouth-motion layer
→ captions/text overlays
→ music/SFX
→ grade/glitch/filter layer
→ final render
→ analysis/iteration
```

Each component should be swappable, cacheable, and independently reviewable.

## Layer categories

| Layer | Examples | Generated by | Reusable? |
|---|---|---|---|
| Character | seal host, AI influencer, fake spokesperson, mascot | image gen, photo import, Jimeng, Nano Banana-like image model | yes |
| Pose/performance | talking head, hand gesture, glance, nod | video gen, lipsync, motion model | sometimes |
| Background | office, podcast studio, surreal math/rocket board, street interview | image/video gen | yes |
| Props | dangling keys, graphs, product package, whiteboard, phone UI | image gen, local compositing | yes |
| Dialogue | hook, punchline, explainer, product claim | LLM/script node | yes |
| Audio | TTS voice, music bed, SFX, room tone | TTS/SFX/local libraries | yes |
| Captions | subtitles, kinetic typography, disclaimers | local render/ffmpeg/Remotion | yes |
| Effects | CapCut-style filters, brainrot overlays, zooms, glitches | local ffmpeg/Remotion/CapCut reverse | yes |
| Analysis | Gemini/Grok/heuristic scores | analysis node | yes |

## Node graph model

A graph node is a pure-ish transform whenever possible:

```yaml
- id: seal_character
  kind: asset.character
  provider: jimeng.image
  input:
    prompt: $prompts.seal_character_zh
  output:
    image: seal_character_png

- id: dangling_keys_prop
  kind: asset.prop
  provider: local-or-imagegen
  input:
    prompt: "dangling keys, transparent background, toy-like, absurdist"
  output:
    image: keys_png

- id: compose_scene
  kind: scene.compose
  provider: local
  needs: [seal_character, dangling_keys_prop]
  input:
    layers:
      - asset: $outputs.background.image
        z: 0
      - asset: $outputs.seal_character.image
        z: 10
      - asset: $outputs.dangling_keys_prop.image
        z: 20
        animation: bob-left-right
  output:
    image: scene_keyframe_png
```

## Serialization implications

The recipe format should support:

- DAG `needs` dependencies
- stable asset IDs
- asset libraries, not just one-off files
- layer stacks with z-index, blend mode, masks, transforms, and simple animations
- provider-specific generation nodes
- local deterministic composition nodes
- manifests with hashes for every intermediate artifact

A future recipe should be able to say:

```yaml
assetLibraries:
  brainrot_props:
    uri: file://data/assets/brainrot-props/index.json
  characters:
    uri: file://data/assets/characters/index.json

scenes:
  talking_head_base:
    layers:
      - ref: $assets.backgrounds.future_city
      - ref: $assets.characters.seal_host
      - ref: $assets.props.dangling_keys
      - ref: $assets.props.math_rocket_overlay
```

## Prototype strategy

For the current talking-seal prototype:

1. Treat the seal screenshot as a **character/reference asset**, not the whole final video.
2. Generate/collect separate background and brainrot props.
3. Generate base motion with no text.
4. Generate TTS independently.
5. Add subtitles locally.
6. Test lipsync separately; if it fails, use stylized mouth-flap or no-lipsync with strong captions.
7. Keep every intermediate artifact in the run manifest.

## AI UGC extension

For less-brainrot AI UGC later, the same graph can swap:

- `character=seal` → `character=ai_influencer/persona`
- `background=surreal math board` → `background=bedroom/car/podcast/street/office`
- `dialogue=post-labor joke` → `dialogue=product hook/testimonial`
- `effects=glitch brainrot` → `effects=CapCut-style clean captions + jump cuts`
- `analysis=surreal quality` → `analysis=UGC hook/retention/compliance rubric`

The graph should also support cloning popular formats ethically by capturing high-level structure, not copying identities or proprietary content verbatim.

## Near-term implementation recommendation

Do not build a full graph runner yet. First:

1. Encode graph concepts in YAML recipe schema.
2. Make `asset` and `stage output` references explicit.
3. Add local deterministic nodes first: subtitles, ffmpeg compose, mux, analysis.
4. Add Jimeng/TTS/lipsync provider nodes only after API research stabilizes.
5. Keep CapCut reverse engineering as a separate lane if needed.
