Bottom line You can recreate most of the useful workflow shape of Rork without using Rork: natural-language idea → generated product spec → generated screens/components → working Expo/React Native or web app → iterative review → deployed beta. The right mental model is not “one giant prompt builds the app.” It is a small AI-assisted product studio where: ChatGPT Pro = product manager, UX lead, architect, reviewer. Codex = implementation agent, refactorer, tester, PR author, bug fixer. GitHub/repo/CI = source of truth. You = product owner and final quality authority. Rork’s own public FAQ says its cross-platform mode uses React Native and Expo, while its native Apple-focused mode uses SwiftUI. That makes Expo/React Native the closest practical baseline for a Rork-like pipeline that can ship iOS, Android, and web from one codebase or near-one codebase. Rork 1. Risks and limitations 1. “One prompt to app” is a trap Rork abstracts away the pipeline. You are replacing that abstraction with disciplined steps. If you skip the steps, you get a pile of generated code that is hard to fix. 2. Codex can overbuild It may add libraries, abstractions, and patterns you did not ask for. Control this with: - AGENTS.md- small tickets- explicit non-goals- dependency approval rules- CI gates 3. Context drift is real ChatGPT may refine the product in one direction while Codex implements an older spec. Prevent this by making the repo docs canonical. Every major decision should update: docs/01-prd.mddocs/03-screen-map.mddocs/05-data-model.mddocs/decisions/* 4. Generated UI often lacks taste Codex can build functional UI, but product taste still needs a human or design-review loop. Use screenshots, not descriptions alone. Ask ChatGPT to critique actual screens. 5. Native mobile edge cases are painful Push notifications, subscriptions, HealthKit, background location, Bluetooth, widgets, Live Activities, and deep native modules can break the smooth Expo path. Rork Max claims native SwiftUI/Xcode cloud handling for Apple-specific features; without that, you will need normal native mobile expertise for advanced platform features. Rork 6. App-store compliance cannot be delegated fully Apple’s review process covers safety, performance, business, design, and legal categories.
